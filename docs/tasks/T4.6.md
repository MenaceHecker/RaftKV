## Goal
`internal/client`: an exported Go client over `KVService` that the gateway wraps. It finds the leader from `NotLeader` hints and `Status`, rotates across a static node list, backs
off with bounded jittered exponential delay (injected `Clock`/`Rand`), and retries a write with the SAME `(clientID, seq)` so a retry is applied at most once. It reports
"outcome unknown" as a distinct error. `cmd/raftkvctl` is a thin CLI over it (get, put, delete, status).

## Design
**Package `internal/client`.** `New(Config) (*Client, error)`; `Config{Addrs []string (non-empty, static), ClientID uint64, StartSeq uint64, DialOpts []grpc.DialOption, Connect func(addr string) (KV, io.Closer, error)
(test seam, default dials insecure gRPC and wraps `KVServiceClient`), PerAttempt time.Duration, Backoff{Initial, Max, Multiplier}, Rand, Clock}`. `Clock{Now(); NewTimer(d) Timer}` and `Rand{Int63n(n int64) int64}` are local
interfaces with real implementations. Total deadline = the caller's `ctx` (a missing deadline gets `DefaultTotal` 30 s). Methods: `Get(ctx,key) ([]byte,bool,error)`, `Put(ctx,key,value) error`, `Delete(ctx,key) error`,
`Status(ctx) (NodeStatus,error)` (asks the current candidate node, no retries across nodes beyond rotation), `Close() error` (closes every conn, idempotent, unblocks waiters). Connections are dialed lazily with
`grpc.NewClient` and cached per address; a hint address not in `Addrs` is dialed and cached too, but rotation uses only `Addrs` (the hint may be an internal name; bounded to 2 x len(Addrs) extra conns).
**Loop** (per operation; one `seq` allocated BEFORE the first attempt and reused on every retry): pick current node; attempt with a `PerAttempt` timeout from the Clock timer cancelling the call context. On `NotLeader`
with an address: switch to it and retry with NO delay at most once per distinct hint per op (loop guard), else backoff. Empty hint, `Unavailable`, `Aborted`, attempt timeout: rotate to the next `Addr`, sleep
`min(Max, Initial*mult^n)` with full jitter `Rand.Int63n(cap)+1` (never zero), via the Clock timer (no `time.Sleep`). After a full rotation with no leader the delay keeps growing to `Max`. `Get` is idempotent and retried
the same way. A successful node is remembered as the next first choice.
**Errors (taxonomy).** `ok` = nil. `*DefinitiveError{Code, Err}`: the write cannot have been applied: no attempt was sent (ctx already done, `Close`d, bad key), or the server returned
`InvalidArgument`, `PermissionDenied`, `Unauthenticated`, `Unimplemented`, `ResourceExhausted`. `*IndeterminateError{Attempts, Cause, Seq}`: a write attempt was sent and the op ended in anything else:
deadline/cancel after a send, `Aborted`, `Unavailable`, `DeadlineExceeded`, `NotLeader` (any, see Facts), `Internal`, connection loss. This is conservative and mirrors D5. `Get` never returns Indeterminate: its failure
is `ErrUnavailable` (no leader reached before the deadline; definite for a read) or the ctx error. All errors support `errors.Is/As` and wrap the cause. Helper `IsIndeterminate(err) bool`.
**Gateway mapping:** `Indeterminate` -> 504 with `"outcome":"unknown"` (D5 "Errors to HTTP"); `ErrUnavailable` or Definitive after no send -> 503 + `Retry-After`; `InvalidArgument` -> 400. The gateway must
NOT blindly resubmit an unknown write from a new request: it may use a new seq, and a late commit of the old one is dropped by dedupe only if the same client id's newer seq already applied (see below).

**Sessions and seqs.** `Put`/`Delete` take an internal write mutex (acquired with ctx; a waiter returns Definitive "no attempt sent" if ctx ends while waiting), so a `Client` is safe for concurrent use and **never has
two writes in flight under one client id**. Why: the server drops `seq <= lastSeq` and still reports success (`session.go:43-47`), so two concurrent writes applied in the opposite order would silently lose the
lower one while the client sees `ok`. `Get` needs no lock. Throughput comes from many Clients (D5's pool of 8), each with its own id. After an Indeterminate result the next op gets a strictly greater seq; a late
commit of the abandoned entry then has `seq <= lastSeq` and is dropped, so it can never overwrite the newer write.
**Client id and start seq.** `ClientID == 0` in Config = draw a non-zero random 63-bit id from the injected `Rand` at `New` (id 0 means "no dedupe", `proto:240`); `StartSeq` 0 = 1. A fresh random id has no session, so
seq 1 is safe. **HAZARD (OPEN QUESTION 1):** a fixed id reused across process restarts with seq restarting at 1 has its writes silently dropped as duplicates yet reported `ok`, until seq passes the old high-water mark, and
the table has no expiry to reset it (`session.go:43-47`). The client cannot read the high-water mark (no RPC). Default is therefore random ids; a caller that sets `ClientID` owns `StartSeq` (documented in the
godoc and `raftkvctl --help`). Second, smaller hazard: if a session is evicted (`session.go:58-79`) between an attempt and its retry, the retry is applied again (duplicate); this needs 4096 other new sessions to commit
during one op's retry window, and each restart with a random id adds one session, so a gateway that restarts often shrinks that margin. No mechanism is invented here.

**`cmd/raftkvctl`** (stdlib `flag` + `internal/client`, about 120 lines): `raftkvctl --nodes a,b,c [--client-id N] [--timeout 5s] get K | put K V | delete K | status`. Value from arg or `-` for stdin. `get` miss exits 1 with
"not found"; indeterminate exits 3 with "outcome unknown" on stderr; definite failure exits 2. `status` queries every node and prints id, state, term, leader. No config files, no TLS, no admin RPCs, no membership.

## OPEN QUESTIONS for the human
1. **Session high-water-mark hazard** (above): a restarted process reusing a client id with a lower seq loses writes silently while reporting ok; the server has no expiry and no RPC to read the mark. Accept random ids per
   process (this card), or open a separate card for a server-side fix (for example, reject `seq <= lastSeq` with a distinct error, a raft-adjacent change)? The gateway must not use fixed ids until decided.
2. **Unknown classification is conservative**: every `NotLeader` on a write is Indeterminate, so a pure election-gap failure reports "unknown" although nothing was proposed. Accept, or add a server-side signal
   (needs a node change)?
3. **Per-op defaults**: `PerAttempt` 2 s, `Backoff` 20 ms to 1 s, `DefaultTotal` 30 s (gateway passes its own 3 s ctx per D5). Confirm.
4. **Serialising internally** (this card) vs documenting not-safe (D5 allowed either). Chosen for safety; costs head-of-line blocking per Client. Confirm.
5. No `goleak` dependency (leak test via goroutine count). Accept, or allow adding `go.uber.org/goleak`?
