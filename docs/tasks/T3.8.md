## faultfs model (decided)
- Inode: `durable []byte`, `live []byte`. `Write` extends `live`; `File.Sync` sets `durable = live` (data **and** length);
  `Truncate` changes `live` only and is **not durable until the file is synced** (an unsynced truncate may revert on `Crash`).
- **Directories are inodes too.** Each has `liveEntries` and `durableEntries` (name to inode). `MkdirAll` adds the missing components to
  their parents' live entries; a directory exists after `Crash` only if its entry in the parent was made durable by `SyncDir(parent)`.
  Create, Remove, Rename change live; `SyncDir(d)` copies live to durable for `d` only. Rename is atomic. Data, entry and directory-creation
  durability are independent: a synced file whose entry was never dir-synced vanishes; a synced file in a directory whose own entry
  was never synced vanishes with it; a durable entry with unsynced data comes back with its durable bytes, possibly none.
- `Crash(opts)`: live := durable everywhere, **all open handles become stale** (later ops on them return `ErrStaleHandle`, never
  touching the new state) and **the simulated process lock table is cleared** (as a dead process releases its flocks), so reopen can lock.
  Per file, with `d = durable`, `l = live`:
  - `l` extends `d` (`len(l) >= len(d)`, `l[:len(d)] == d`): `TornTail` keeps `d + l[len(d):k]`, k from the seed (mid-header cuts
    included); `GarbageTail` keeps the length of `l`, unsynced bytes replaced by seeded random bytes; drop keeps `d`.
  - otherwise (truncated or rewritten, `len(l) < len(d)` or prefix changed): the outcome is **`d` or `l`, chosen by the seed**
    (option `TruncateLost`/`TruncatePersisted` forces one). Never slice `l[len(d):k]` here.
  - `TornTailAt(name, keep)`: keep exactly `keep` bytes of that file's unsynced appended data (used by T3.12). `Unsynced(name) int`
    reports the unsynced appended byte count. `SyncAll()` makes everything durable (test setup, T3.10).
- `CrashAt(n)`: op n (every `FS` and `File` method counts) returns `ErrCrashed` before taking effect; `CrashAfter(n)` applies it
  first. Later ops fail with `ErrCrashed`. Because every later op fails, **`CrashAt` cannot show that the code under test refuses
  later writes**; T3.9 uses one-shot faults for that. Tests dry-run the workload to learn N and loop n = 1..N; they assert N > 0
  and the loop count equals N.
- `Inject(Rule{Op, PathGlob, Nth|Prob|Sticky, Err})`: `Nth` is **one-shot and recoverable** (only the nth matching call fails, later
  calls succeed); `Sticky` fails every matching call from the nth on. Errors: `ErrSync` (EIO), `ShortWrite(k)` (writes k bytes, then
  returns a **non-nil** error such as `io.ErrShortWrite`), `ENOSPC` on Write/OpenFile/Truncate/MkdirAll, `ErrRename`, `ErrSyncDir`.
  After a failed Sync, unsynced bytes of that file are kept or dropped by seed at the next `Crash`.
- Randomness only from a `rand.New(rand.NewSource(seed))` passed in; no `time`, no global `rand`, no `os` (AST test, like
  `internal/determinism`). Same seed gives the same trace.

## Tests to write FIRST (all must pass against today's code + T3.7)
**Shared checker** `checkRecovered(t, model, inflight, policy)` after every reopen. `model` follows what the caller was told:
each acked `Append` truncates the model log from its first index and appends (so entries a later acked conflicting append replaced
are **not** required), each acked `CreateSnapshot`/`ApplySnapshot` drops entries at or below its index (snapshot-covered entries are
**not** required). Then: `Open` returns nil; the recovered log above the recovered snapshot index equals `model` (`SyncAlways`) or a
prefix of `model` (`SyncNever`), followed by a prefix of in-flight entries; contiguous from snapshot+1; `HardState.Term >=` the last
acked and `VotedFor` consistent; snapshot index <= last index; snapshot + tail rebuilds the same `statemachine` state
(as `disk_test.go:243`).
1. `TestFaultFSModel`: unsynced bytes lost; unsynced create lost; synced file with unsynced entry lost; **synced file in a directory
   whose entry in the parent was never synced lost (also for new ancestors)**; unsynced rename reverts; synced rename survives; TornTail
   keeps a prefix; GarbageTail keeps the length; **truncate then Crash without file Sync reverts (or persists, forced by option);
   truncate then Sync then Crash persists; `len(live) < len(durable)` never panics and yields `d` or `l`**; **after Crash old
   handles return `ErrStaleHandle` and a second `Lock` on the same dir succeeds**; one-shot `Nth` fails once and then recovers;
   `ShortWrite(k)` returns an error; same seed same result; T3.6's `TestOSFSContract` table passes.
2. `TestRenameBeforeDataIsNotDurable`: create temp, write, **no** file Sync, Rename, SyncDir, Crash: the final name exists with zero or
   torn content, and the snapshot loader (`snapshot.go:164-186`) rejects it and falls back to the older snapshot. Also a
   Sync-then-Rename-without-SyncDir run: the old name survives.
3. `TestCrashAtEveryOpDuringAppend` (`SyncAlways`): batches of 1 and 3 entries, small `SegmentSize` so one roll occurs (`wal.go:295`,
   `:300`); modes drop, torn x seeds 1-5, garbage x seeds 1-5 (garbage relies on T3.7). Nothing acked is lost.
4. `TestCrashAtEveryOpDuringSuffixTruncate`: append 1..10 at term 1, then a conflicting `Append` from 6 at term 2 (`wal.go:259`).
   Before the second ack the log is old 1..10 or 1..5 plus a prefix of the new entries; never old 7..10 after new 6.
5. `TestCrashAtEveryOpDuringSnapshotWrite`: `CreateSnapshot` (`snapshot.go:107-133`, `disk.go:257-275`) under `SyncAlways`: temp file
   never loaded; old or new snapshot loads; nothing below the loaded snapshot is needed.
6. `TestCrashAtEveryOpDuringCompaction` (`SyncAlways` only): `TruncateBefore` (`wal.go:431-469`). HardState never rolls back; all entries
   above the snapshot present; `validateContiguous` passes; state machine rebuild equal.
7. `TestApplySnapshotCrashPoints` (`SyncAlways`): acked snapshot is durable and loads; WAL meta never ahead of the snapshot file
   (`disk.go:85`); entries above `snap.Index` are not asserted here (T3.11).
8. `TestFsyncFailureIsNotAcked`: `ErrSync` on `Append`, `SetHardState`, `CreateSnapshot`: the call returns an error; the post-crash state
   satisfies the checker with the failed entry counted as in-flight. (Whether later writes are refused is T3.9.)
9. `TestShortWriteAndENOSPC`: one failing write, then **immediate Crash** with no further writes: reopen is clean or repaired and
   unacked. ENOSPC on roll create and on snapshot temp: no ack, clean reopen.
10. `TestSyncNeverContract` (no compaction, **no segment roll**: `SegmentSize` large enough that one segment holds everything; an
    unsynced roll is T3.12): after `Crash`, any suffix of entries and of unsynced HardState updates may be lost; no hole, no reorder,
    `Open` succeeds, snapshots (always fsynced, `snapshot.go:118`) are never lost. A process crash (no `Crash()`) loses nothing
    (`wal_test.go:523`).
11. `TestRepairIsDurable` (moved from T3.7): a segment with a bad tail; crash at/after each repair op (`Truncate`, file `Sync`,
    `SyncDir`) under drop, torn and garbage; reopen, then **crash again** and reopen: the second open never errors, earlier entries
    stay intact, and once all repair ops completed the tail does not return.
12. `TestCrashDuringRepairThenSecondCrash`: `CrashAt` inside the repair, reopen (which repairs again), `Crash` once more, reopen.
13. `TestRandomWorkloadWithCrashes`: seeds 1-200 (`-short`: 20) over Append, conflicting Append, SetHardState, CreateSnapshot under
    `SyncAlways` with no injected sync failures and no `ApplySnapshot`; one random crash point per run; two generations (handles and
    locks from generation 1 are stale and released by the crash); seed in every failure message.
