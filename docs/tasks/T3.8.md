## faultfs model (decided: simple SyncDir model)
- Inode: `durable []byte`, `live []byte`. `Write` extends `live`; `File.Sync` sets `durable = live`; `Truncate` changes `live`.
- Per directory: `liveEntries`, `durableEntries` (name to inode). Create, Remove, Rename change live; `SyncDir(d)` copies live to
  durable for `d` only. Rename is atomic. Data and entry durability are independent: a synced file whose entry was never
  dir-synced vanishes on `Crash`; a durable entry with unsynced data comes back with its durable bytes, possibly none.
- `Crash(opts)`: live := durable everywhere. `TornTail`: per file with unsynced appended bytes keep `durable + live[len(durable):k]`,
  k from the seed (mid-header cuts included). `GarbageTail`: size kept, unsynced bytes replaced by seeded random bytes. `TornTailAt(name, keep)`:
  keep exactly `keep` bytes of that file's unsynced data (used by T3.12). `Unsynced(name) int` reports the unsynced byte count.
- `CrashAt(n)`: op n (every `FS` and `File` method counts) returns `ErrCrashed` before taking effect; `CrashAfter(n)` applies it
  first. Later ops fail. Tests dry-run the workload to learn N and loop n = 1..N; they assert N > 0 and the loop count equals N.
- `Inject(Rule{Op, PathGlob, Nth|Prob, Err})`: `ErrSync` (EIO), `ShortWrite(k)`, `ENOSPC` on Write/OpenFile/Truncate, `ErrRename`,
  `ErrSyncDir`. After a failed Sync, unsynced bytes of that file are kept or dropped by seed at the next `Crash`.
- Randomness only from a `rand.New(rand.NewSource(seed))` passed in; no `time`, no global `rand`, no `os` (AST test, like
  `internal/determinism`). Same seed gives the same trace.

## Tests to write FIRST (all must pass against today's code + T3.7)
Checker `checkRecovered(t, acked, inflight, policy)` after every reopen: `Open` returns nil; every acked entry present and equal;
log contiguous from snapshot+1 and equal to acked followed by a prefix of in-flight; `HardState.Term >=` last acked and `VotedFor`
consistent; snapshot index <= last index; snapshot + tail rebuilds the same `statemachine` state (as `disk_test.go:243`).
1. `TestFaultFSModel`: unsynced bytes lost; unsynced create lost; synced file with unsynced entry lost; unsynced rename reverts; synced
   rename survives; TornTail keeps a prefix; GarbageTail keeps the length; same seed same result; T3.6's `TestOSFSContract` table passes.
2. `TestRenameBeforeDataIsNotDurable` (the one targeted rename test): create temp, write, **no** file Sync, Rename, SyncDir, Crash:
   the final name exists with zero or torn content, and the snapshot loader (`snapshot.go:164-186`) rejects it and falls back
   to the older snapshot. Also a Sync-then-Rename-without-SyncDir run: the old name survives.
3. `TestCrashAtEveryOpDuringAppend` (`SyncAlways`): batches of 1 and 3 entries, small `SegmentSize` so one roll occurs
   (`wal.go:295`, `:300`); modes drop, torn x seeds 1-5, garbage x seeds 1-5 (garbage relies on T3.7). Nothing acked is lost.
4. `TestCrashAtEveryOpDuringSuffixTruncate`: append 1..10 at term 1, then a conflicting `Append` from 6 at term 2 (`wal.go:259`).
   Before the second ack the log is old 1..10 or 1..5 plus a prefix of the new entries; never old 7..10 after new 6.
5. `TestCrashAtEveryOpDuringSnapshotWrite`: `CreateSnapshot` (`snapshot.go:107-133`, `disk.go:257-275`) under `SyncAlways`:
   temp file never loaded; old or new snapshot loads; nothing below the loaded snapshot is needed.
6. `TestCrashAtEveryOpDuringCompaction` (`SyncAlways` only): `TruncateBefore` (`wal.go:431-469`). HardState never rolls back; all entries
   above the snapshot present; `validateContiguous` passes; state machine rebuild equal.
7. `TestApplySnapshotCrashPoints` (`SyncAlways`): acked snapshot is durable and loads; WAL meta never ahead of the snapshot file
   (`disk.go:85`); the question of entries above `snap.Index` is not asserted here (T3.11).
8. `TestFsyncFailureIsNotAcked`: `ErrSync` on `Append`, `SetHardState`, `CreateSnapshot`: the call returns an error; the post-crash state
   satisfies the checker with the failed entry counted as in-flight. (Whether later writes are refused is T3.9.)
9. `TestShortWriteAndENOSPC`: one failing write, then **immediate Crash** with no further writes: reopen is clean or repaired and
   unacked. ENOSPC on roll create and on snapshot temp: no ack, clean reopen.
10. `TestSyncNeverContract` (no compaction, no HardState-rollback assertion across a compaction): after `Crash`, any suffix of
    entries and of unsynced HardState updates may be lost; no hole, no reorder, `Open` succeeds, snapshots (always fsynced,
    `snapshot.go:118`) are never lost. A process crash (no `Crash()`) loses nothing (`wal_test.go:523`).
11. `TestRandomWorkloadWithCrashes`: seeds 1-200 (`-short`: 20) over Append, conflicting Append, SetHardState, CreateSnapshot under
    `SyncAlways` with no injected sync failures and no `ApplySnapshot`; one random crash point per run; two generations; seed in every
    failure message.
