## Goal
Give an operator and the demo gateway a control surface on each node: read status, crash it, pause it, partition it, add network loss and
delay, and watch a stream of state-change events. Faults are applied in a wrapper around `node.Transport` and in the node run loop, so they
are **application-level**; the docs must say so (RUNBOOK §10.5). With the admin listener off, or no fault set, Raft behaviour is unchanged.

## Invariants touched
RUNBOOK §7.1 and §7.2 are **not** changed; the wrapper only drops or delays messages, which Raft already tolerates. `internal/raft` is not
edited. §2: no `time.Now`/`math/rand` in `internal/raft` (unaffected); wrapper and admin code take an injected clock and rand for tests.

## Decisions (human, binding)
1. **Admin listener.** New `--admin-listen` (off by default). Destructive RPCs (`Crash`, `Pause`, `SetPartition`, `SetNetem`) also need
   `--admin-chaos`; without it they return `PermissionDenied`. When the listener is on, every RPC (streams included) requires a token from
   `--admin-token-file` (gRPC metadata `authorization: Bearer <token>`), compared in constant time. The server **refuses to start** the
   listener if the flag is set without a token file, or the file is missing or empty. Missing and wrong tokens both return
   `Unauthenticated` with the same message. The token is never logged.
2. **Crash.** No `restartDelay` field in the proto. The RPC replies, then exits after about 50ms with `os.Exit(137)`; no deferred cleanup,
   no graceful `Stop`. The supervisor (systemd `RestartSec`) restarts the process.
3. **Status.** The existing `KVService.Status` fields (`node_id, leader_id, leader_address, term, state, commit_index, applied_index`) plus
   `members`, `joint`, `first_index`, `last_index`, `snapshot_index`.
4. **Election events** are derived from term and role changes observed in `internal/node`. No change to `internal/raft`. Limitation, to be
   stated in `docs/observability.md`: no per-vote or candidate-round detail. Backlog item: a raft observer hook.
5. **Pause(d).** While paused: ticks stop, peer messages are dropped in both directions, client RPCs (`KVService`, `ClusterService`) return
   `Unavailable`, and committed-entry apply is frozen. `Status` and `Events` keep working. Hard cap 60s: a larger `d` is clamped to 60s and
   the node auto-resumes. **All injected faults** (partition, delay, drop) expire at the node after 120s unless re-set. Document that this
   models a frozen process at the application level, not an OS stop (no SIGSTOP, no kernel state).

## Facts from the code (at a632530)
- `node.Transport` is one method, `Send([]raft.Message)` (`internal/node/node.go:27`). `PeerTransport.Send` (`transport/peer.go:196`) delivers
  to self directly and queues for peers. Blocking outbound alone cannot stop a peer sending to this node, so the inbound side needs a
  filter in `RaftServer.Deliver` (`peer.go:352`).
- `node.Status` (`node.go:107`) has `ID, Leader, Term, State, Commit, Applied, Members, SnapshotsReceived`; first/last/snapshot index come
  from the raft log and need a small accessor in `internal/node` (not `internal/raft`) if not already exposed (check first).
- Events source today: `Recorder.LeaderChanged` (fired from `observeLeadership`, `node.go:780`), `SnapshotCreated`, `SnapshotReceived`. Nothing
  reports commit/applied movement or state changes other than via leader change.
- `cmd/raftkv-server` serves Raft, KV and Cluster on one `--listen` port plus `--metrics-listen` (`main.go:171-173`).
- The run loop (`node.go:359`) owns ticking and `processReady` (`:500`); the pause gate belongs there.

## Implementation notes
- Dropped messages are lost, never altered; do not touch `raft.Message` contents. Delay must not block `Send`; keep order per peer.
- The pause gate must hold apply without losing committed entries; on resume apply continues from the same index.
- Events are emitted after state is observed in the run loop, so the stream never shows a state the node did not hold.
- Token comparison uses `crypto/subtle.ConstantTimeCompare` on equal-length digests; never log tokens or request payloads.
