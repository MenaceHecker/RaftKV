# T4.7: admin service, fault wrapper, event stream

Planner: Claude, read-only. Based on `origin/main` a632530 (T3.16 and T3.17 merged). Claims come from reading and were re-checked against
the code after Codex's review; **no test was run**. Branches: `test/t4-7-admin-red` (red tests), then `feat/t4-7-admin`.
Needed by the demo (RUNBOOK §10). The human decisions below are binding.

## Goal
Give an operator and the demo gateway a control surface on each node: read status, crash it, pause it, partition it, add network loss and
delay, and watch a stream of observed state changes. Faults live in a wrapper around `node.Transport`, in the Raft ingress handlers and in
the node run loop, so they are **application-level**; the docs must say so (RUNBOOK §10.5). With the admin listener off, or no fault set,
behaviour is unchanged. `internal/raft` is not edited.

## Invariants touched
RUNBOOK §7.1/§7.2 unchanged: faults only drop or delay messages and stop ticks, which Raft tolerates. §2: no `time.Now`/`math/rand` in
`internal/raft` (unaffected); new code takes an injected clock and rand. Persistence ordering is untouched (`processReady`/`Advance` unchanged).

## Decisions (human, binding)
1. **Admin listener.** `--admin-listen`, off by default. `Crash`, `Pause`, `SetPartition`, `SetNetem` also need `--admin-chaos`, else
   `PermissionDenied`. With the listener on, every RPC (streams too) needs the token from `--admin-token-file` (metadata
   `authorization: Bearer <t>`), constant-time compare; missing and wrong tokens both give the same `Unauthenticated` message. The server
   refuses to start the listener if the file is unset, missing or empty. Never log the token.
2. **Crash.** No `restartDelay`. The handler replies, then `os.Exit(137)` about 50ms later, no deferred cleanup. Reply delivery is
   **best effort**: the handler returning does not prove the client received it. The gateway must treat a connection loss right after
   `Crash` as success. The auth and chaos checks run before anything is scheduled.
3. **Status.** Existing `KVService.Status` fields plus `members`, `joint`, `first_index`, `last_index`, `snapshot_index`.
4. **Events are observed state transitions** of (term, role, leader), deduplicated on the full tuple across both observation hooks
   (`node.go:501` and `:541`). Transitions inside one `Tick`/`Step`/`Advance` are **not guaranteed** to be observed (a candidate round that
   starts and ends between observations is invisible); no per-vote detail. Backlog: a raft observer hook (needs raft-core review).
5. **Pause(d).** Ticks stop; peer messages are dropped both ways (`Deliver` **and** `DeliverSnapshot`, including streams opened before the
   pause); every `KVService` and `ClusterService` method returns `Unavailable`; **apply is not frozen**: committed entries and snapshots
   keep being applied, and `processReady`/`Advance` are untouched. `AdminService.Status` and `Events` stay available. `d` is clamped to
   60s and the node auto-resumes. All injected faults (partition, delay, drop) expire at the node 120s after being set, each on its own
   timer. Docs: this models a frozen process at the application level, not an OS stop.
6. **Security scope.** The auth token, `--admin-chaos` and the default-off listener guard the **admin fault RPCs only**. The shared
   listener still accepts unauthenticated `AddNode`/`RemoveNode` and snapshot streams of up to 1 GiB each with no aggregate or concurrency
   bound. Both are pre-existing and **out of scope here**; they are listed under Backlog as proposed card **T3.18**.

## Facts from the code (a632530)
- `node.Transport` has one method, `Send` (`node.go:27`). `reconcileTransport` (`node.go:731`) type-asserts `Reconfigurable`
  (`AddPeer`/`RemovePeer`) and **silently does nothing** if the transport lacks it, so a wrapper without them leaves new peers unreachable.
- Two ingress paths call `node.Step`: `RaftServer.Deliver` (`peer.go:352`) and `DeliverSnapshot` (`peer.go:364`, which buffers up to
  `MaxSnapshotBytes` = 1 GiB per stream, `:390-393`). `PeerTransport.Send` (`peer.go:196`) delivers to self directly; the wrapper must never
  drop self-addressed messages.
- `KVServer.Status` and `ListMembers` read through `Node.Status()` -> `statusc` in the run loop (`node.go:269,395`). The pause gate must not
  block that select case.
- `grpc.NewServer()` has no options (`main.go:171`): no interceptors, no stream or size limits. `KVServer.Register` registers both `KVService` and
  `ClusterService` (`kvserver.go:47-50`).
- `observeLeadership` (`node.go:780`) compares term and leader only. `node.Status` starts at `node.go:105`.

## Implementation notes
- Dropped messages are lost, never altered. Delay never blocks `Send`; keep per-peer order. The pause gate is a flag checked at the tick
  and the ingress; do not block the run loop.
- Event caps are constants (subscribers 16, buffer 256 per subscriber); on overflow end that stream with `ResourceExhausted`.
- Constant-time compare via `crypto/subtle` on equal-length digests.
