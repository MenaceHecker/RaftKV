# T6.4: flake-guard, a PR-time CI guard for new and changed tests
## Goal (2-3 sentences)
Roughly ten consecutive CI failures in November 2026 were test races seen only on the 2-core runner (PRs #32, #43, #47, #48, #51, #52 by title; #41 is titled "chaos controller (D5b)", so the fake-clock-driver fix inside it is UNVERIFIED), never on a laptop and not caught by the hook (`go test -race -short ./...`, .githooks/pre-commit:12). Add `scripts/flake-guard.sh` plus a `flake-guard` job that re-runs only the tests a PR adds or changes, many times, in the three CI modes, so the race shows up on the PR that introduces it. RUNBOOK §6.4 already calls one failure in `-count=20` a P0 bug; this enforces it where it is cheap.
## Invariants touched (RUNBOOK §7 refs)
None in §7. Enforces RUNBOOK §2 rule 6 and §6.4. Do not weaken: the guard never retries a failure to turn it green.

## Design
1. Selection (no bypass by renaming). `git diff -U0 BASE...HEAD -- '*_test.go'`; for each changed hunk, parse the post-image file and map hunk line ranges to the enclosing top-level `func` decl. A hunk inside a `TestXxx`/`FuzzXxx` selects it; a hunk inside a non-Test helper (spy, driver, fake clock) selects every Test in the same package that references that helper (go/types or a name scan within the package). A new/renamed file selects all its tests; a rename or delete+add is seen because selection is by post-image content, not by name. A changed non-test file under internal/gateway or internal/transport selects the whole-package pass only. Subtests ride with their parent. Regex is `^(A|B|C)$` per package, built from exact names (QuoteMeta).
2. Runs per package P with selected tests T (`-count=20`, `-timeout 10m`, `-run`, `-failfast=false`, `-json`):
   plain `go test`; `GOMAXPROCS=1 go test`; `go test -race`. Always `-count`, never cached.
3. Whole-package pass for `./internal/gateway` and `./internal/transport` (if the PR touches either package's tests or source): `-count=3`, plain and `GOMAXPROCS=1` (no race, already covered by ci.yml:88).
4. Report: parse `-json`; emit a table `mode | package | test | failures/runs`, write to `$GITHUB_STEP_SUMMARY`, and a `::error file=...::` annotation per failing test naming mode and count. First failure's output (30 lines) is attached. Exit 1 if any failure. Also print the exact local command: `make flake-guard BASE=origin/main` and the single-test form `go test -race -count=20 -run '^TestX$' ./pkg`.
5. No tests added or changed: print "flake-guard: no test changes, nothing to run", still run step 3 if gateway/transport source changed, else exit 0 in seconds (job is skipped-green, never absent, so it can be required).
6. Required vs advisory: ship ADVISORY (`continue-on-error: true` for two weeks, summary still red), then make required once the false-failure rate is known. A failure is a P0 by §6.4, so required is the end state. No retry-to-green and no label override; the human merging decides on a red advisory run.
7. Budget (ESTIMATE, not measured): a typical PR touching 3 to 6 tests in one package, each 1 to 5 s: 20 runs x 3 modes about 3 to 10 min, race about 2x plain. Whole-package pass: gateway+transport suite time is not measured here (a standalone measurement is the first step of the executor); at about 40 s plain per package that is 3 x 2 x 40 = 4 min. Cap at 25 min job timeout; if the selection exceeds 40 tests, drop to `-count=10` and say so in the summary (never silently).
8. LOAD variant (`LOAD=1`, a separate matrix leg, advisory): run `cmd/cpuhog` with 2 busy goroutines pinned alongside the selection in plain and race modes only, to approximate the packages-in-parallel contention that deposed the 100 to 190 ms election timeout (#51). Cost: another 1x plain + 1x race pass. Worth it for tests that use real timers (transport, gateway live-adapter); skip for pure fake-clock raft tests. Recommend: run it only when a selected package is gateway or transport. Caveat: hogging also slows the test runner, so it can false-positive on tests with a genuinely small deadline; that is the point, but expect to tune hog count (UNVERIFIED that 2 goroutines reproduces the CI contention).
## Tests to write FIRST (names, what each asserts)
Written before the script, with a stub `scripts/flake-guard.sh` that exits 0 so they fail on assertions:
- `scripts/flake-guard_test.go` (package main in a new `cmd/flakeguardtest`, or `internal/flakeguard`): builds a temp git repo with a base commit and a PR commit, runs the guard with `SELF=1`.
- `TestGuardFailsOnRacyFixture`: fixture `scripts/testdata/flake/racy/racy_test.go` (build tag `flakefixture`, so `go test ./...` never runs it): a test whose two goroutines read/write a shared int without sync and `time.Sleep` race; asserts guard exit != 0, output names the test, `-race` mode, and a nonzero failure count.
- `TestGuardPassesOnCleanFixture`: a mutex-protected equivalent; asserts exit 0.
- `TestGuardSelectsHelperChange`: PR changes only a helper used by two tests; asserts both are selected.
- `TestGuardRenameStillSelected`: PR renames a test function; asserts the new name runs.
- `TestGuardNoTestChanges`: PR changes only a README; asserts exit 0 and the "nothing to run" line.
- `TestGuardSelectionIsExactNames`: names with regex metacharacters (`TestA_B`, `TestA/B`) are quoted.
Fixtures are run only by the guard's own test via `-tags flakefixture`; the flaky fixture must fail on every mode within 20 runs (use an explicit `runtime.Gosched` loop plus a fixed-size barrier to make it deterministic enough for `-race`, which flags it on the first run).
## Implementation notes
Use `set -euo pipefail`; never pipe the test exit status through `tee` without `PIPESTATUS`. The guard touches no Raft code, so the §2 rule-7 ban does not apply, but `cmd/cpuhog` and the helper stay outside internal/raft. Add the `// guard:fakeclock`-style convention? No: unrelated. Do not edit scripts/guard-tests.sh; a flake-guard failure is separate from "tests weakened".
## Acceptance criteria
- On a PR that adds the racy fixture test the job is red and names test, mode, and failure ratio; on the clean fixture it is green.
- A PR with no `*_test.go` changes finishes in under 1 minute (including setup) and is green.
- Renaming or moving a test, or editing only a helper, still runs the affected tests.
- Output is reproducible locally with `make flake-guard`.
- The measured wall time of the job on three real PRs is recorded in the PR description (replaces the estimates above).
