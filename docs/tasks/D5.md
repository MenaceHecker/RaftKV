## Facts from the code (cite file:line; re-check before use)
- Binary is `cmd/raftkv-server`, flags not YAML (`cmd/raftkv-server/main.go:53-70`); there is **no `raftkvd`, no `--config`, no `cmd/gateway`**.
- Services on the shared port: `RaftService`, `KVService`, `ClusterService` (`internal/transport/kvserver.go:47-50`, `main.go:333-346`).
  `KVService` has only `Get`, `Put`, `Delete`, `Status` (`raftkv.proto:68-83`). **No CAS exists on the wire or in the state machine**
  (`statemachine/kv.go:16-17` has `OpPut`, `OpDelete` only). **There is no scan or count RPC.**
- Admin: `AdminService` on `--admin-listen`, Bearer token, `Crash`/`Pause`/`SetPartition`/`SetNetem` also need `--admin-chaos`
  (`admin.go:285-322`, `main.go:349-358`). `LoadAdminToken` demands mode 0600 (`admin.go:404`), the node side only.
- Errors: `NotLeader` is an error detail on `FailedPrecondition` (`kvserver.go:64-86`); `Aborted` = leadership lost (`:97`); a pending write that sees
  the node stop leading gets `ErrNotLeader` (`internal/node/node.go:586`) or `ErrLostLeadership` (`:616`), so **a NotLeader reply to a write does not prove
  it did not commit** (unverified by test).
- Dedup: a write with `seq <= lastSeq` of its client id is silently skipped (`statemachine/session.go:40-44`), 4096 sessions, LRU-ish eviction (`:10,55`). One
  client id used by two concurrent requests can lose a **successful** write if seqs apply out of order. Sessions must be serialized per client id.
- The only client code is `cmd/raftkv-bench/main.go:97-200` (package main: `pool`, `redirect`, `rotate`, `notLeader`, `putOnce`). No `internal/client`,
  no `raftkvctl`, no card T4.6 (`docs/tasks/` has none). STATUS.md:105 (stale about `chaosrun`, which now exists) also says no client library found.
- `Node.Get` is a ReadIndex read (`node.go:345`); it needs the leader. The server enforces **no key or value size limit** beyond gRPC's 4 MiB default.

## Prerequisite T4.6 (client library): separate card, separate PR, merged before D5's real adapter
Reason: it is independently testable, reviewed by the human as an API (also used by `raftkvctl`, bench), and D5's other commits do not need it (they use the
fake). Do not hide it inside D5. Minimum spec for the T4.6 planner, to be written as `docs/tasks/T4.6.md`:
`internal/client`: `New(Config{Addrs, ClientID, DialOpts, PerAttempt, Total, Backoff, Rand, Clock})`; `Get`, `Put`, `Delete` (no CAS: no wire support);
follows `NotLeader.leader_address`, rotates on an empty hint, jittered exponential backoff with injected Rand/Clock (no `time.Sleep`); allocates `seq` **once
per operation** and reuses it on every retry; a `Client` is **not safe for concurrent writes** (serialized or documented; use one per worker); returns a typed
`*IndeterminateError` for any write that ended in `Aborted`, `Unavailable`, `DeadlineExceeded`, `NotLeader` after an attempt was sent, or a lost connection, and a
typed definite error only if no attempt was sent. Ctor for per-call gRPC metadata is not needed. Test: kill the leader mid-workload and finish (RUNBOOK T4.6).

## Files to create or change
- `cmd/gateway/main.go`: flags `--listen`, `--nodes`, `--admin-token-file` (HTTP admin and node RPC token, Q2), `--state-dir`, `--dashboard-origin`, `--public-keyspace-reset`
  (default 6h). Fail closed: no `--dashboard-origin`/no token file/no state dir = exit non-zero. HTTP only; **TLS is D6** (listener behind `http.Server`).
- `internal/gateway/cluster.go`: `Cluster` interface (the seam): `Nodes() []NodeInfo{ID,AZ}`; `Status(ctx,id) (NodeStatus,error)`; `NewKV() KV` with `KV{Get,Put,Delete}`
  (one `KV` = one client id, **not** concurrent-write safe, so the gateway keeps a pool of 8 and checks one out per request); chaos methods `Crash`, `Pause`, `Partition`,
  `Netem`, `ClearFaults(id)`; `Events(ctx,id) (<-chan NodeEvent, error)`. **No** `AddNode`/`RemoveNode`/`ListMembers` method exists.
- `internal/gateway/live.go`: real adapter over `internal/client` (T4.6) and `AdminServiceClient`; insecure gRPC inside the VPC, `authorization: Bearer` on every admin call via
  per-RPC metadata; only `KVService` and `AdminService` clients are constructed.
- `internal/gateway/{api,kv,auth,limits,state,poll}.go`: handlers, bounded body, limits, CORS, Bearer auth, state file, status poller (1 Hz cache so public reads never fan out to nodes).
- `internal/gateway/fakecluster/`: in-memory cluster with a scripted leader, crash/restart, partition, pause, a linearizable register and a switchable **lying read** mode.
- Everything uses an injected `Clock` and `Rand` (interfaces local to the package).

## Implementation notes
- Key registry: `--state-dir/keys.log`, append-only `put <key>`/`del <key>` lines, fsync per append, atomic compact (temp, fsync, rename, directory fsync) when it doubles, loaded at start. It is
  the **only** way to enforce the 10,000 cap and to reset the keyspace, because the cluster has no scan (Q3). Reset deletes each registry key through the client, then truncates the log.
- Public keys are stored unmodified (no prefix) except the reserved `__verify/` prefix, which the public API refuses; this keeps verify (D5b) disjoint from public writes.
- Client IP: `RemoteAddr` only (the gateway is on the Internet directly, §10.1); never trust `X-Forwarded-For`. IPv6 limited per /64. Limiter map in memory only, never logged, never persisted.
- Logs: `slog` JSON: method, route template, status, latency, a request id. No path keys, no IP, no headers, no body. Suppress `net/http` error logs that include the remote address.
- Errors to HTTP: indeterminate write -> 504 with `"outcome":"unknown"`; no leader after retries -> 503 + `Retry-After`; `Get` miss -> 404.
- Not applicable here: paper sections. Raft semantics are consumed through the client library only.
