## Goal
`WAL.replay` repairs only `ErrTornRecord` at the tail of the last segment (`wal.go:200`), and does so **unconditionally**: it truncates
even when valid records follow a bad length. A bad CRC, an oversize length or a zeroed tail there makes the node refuse to start,
while RUNBOOK §7.3 calls these a torn write. Truncate only when nothing valid follows the bad record in the last segment; otherwise
return `ErrCorruptWAL`. Count and log every repair.

## Invariants touched (RUNBOOK §7 refs)
§7.3 #2 (this card); §7.2 item 1 and §7.3 #3 (the repair must not touch acked data that is still readable, and the repair itself
must be durable); §7.3 #4 (garbage tail after a crash; the faultfs cases, including repair durability, are in T3.8).

## Behavior specification (decided)
- Last segment only. Any error in an older segment stays `ErrCorruptWAL` (`wal.go:196-199`; `wal_test.go:320`).
- Bad record: the first offset `good` where `readRecord` fails with `ErrTornRecord`, `ErrCorruptRecord` or `ErrRecordTooLarge`.
  **Key on the framing error returned by `readRecord`, never on `errors.Is(err, ErrCorruptRecord)` of a decode error:** `reader.uint64`
  and `reader.bytes` wrap `ErrCorruptRecord` (`record.go:112,122,137`), so a CRC-valid but undecodable record would otherwise look
  repairable. Test 7 guards this.
- Truncate **only if** no offset `p > good` in the remainder of that segment holds a valid record: `readRecord` succeeds, the type is
  known, and the payload decodes (`decodeEntry`, `decodeHardState`, `decodeSnapshotMeta`). Scan cost is O(segment bytes).
  If one is found, damage is mid-log: `ErrCorruptWAL` naming segment and offset, file bytes unchanged. This also covers a damaged
  length that reads as `ErrTornRecord` (it points past EOF) while a valid later record exists (test 5).
- A record with a valid CRC whose type is unknown or whose payload fails to decode is **corruption, not a tear**: refuse
  (`replaySegment` already returns these, `wal.go:229-251`); never reaches the repair path.
- Repair steps: `FS.Truncate` to `good`; open the file, `Sync` it, close; `SyncDir`; set `Replay.Repaired`. Today only `SyncDir` runs
  (`wal.go:206-211`), so the new size is not durable; this adds the file fsync.
- On repair: `slog.Warn` with segment, offset, bytes dropped and the original error; and the counters below. **No flag** disables it.
- Documented residual risk (code comment): a fsynced record later rotted by the media, with nothing valid after it, is
  indistinguishable from a tear and is dropped. The valid-data-follows rule keeps this to the final record(s).

## Tests to write FIRST (plain temp-dir files as in `wal_test.go`; no faultfs)
Existing `wal_test.go:199,223,293,320`, `disk_test.go:440` stay unchanged. **Red** = fails on current code; **control** = green today and after.
Every mutation test first asserts `!bytes.Equal(before, after)` (xor 0xff always changes a byte; zeroing may not).
1. **Red** `TestBadCRCAtTailIsRepaired`: flip one payload byte of the last record; `Repaired`, earlier entries kept, no error.
2. **Red (mixed)** `TestBadTailIsRepairedAtEveryByte`: xor 0xff at each byte of the last record. Length-byte flips that grow past EOF
   are already `ErrTornRecord` (green today); CRC, type, payload and shrinking-length flips are red. The red-commit report lists the
   per-offset outcome before the fix. Open succeeds with earlier entries intact. Mirrors `wal_test.go:223`.
3. **Red** `TestOversizeLengthAtTailIsRepaired`: last record's length = 0xFFFFFFFF.
4. **Red** `TestZeroedTailIsRepaired`: last N bytes zeroed, N in {1, 8, 64, 4096}; the last record carries >= 8 KiB of data so zeroing
   4096 bytes never reaches the preserved earlier records, and a case whose zeroed bytes were already zero is rejected by the check above.
5. **Red** `TestDamagedLengthBeforeValidRecordIsRefused`: three records; record 2's length is raised so `readRecord` returns
   `ErrTornRecord` (it runs past EOF) while record 3 is valid. Today's unconditional truncation silently drops record 3 (acked data).
   After the fix: `ErrCorruptWAL`, `Repaired` false, file bytes unchanged.
6. **Control** `TestBadRecordFollowedByValidRecordIsRefused`: a CRC-damaged record 2 followed by valid record 3 (`wal_test.go:293`
   style); `ErrCorruptWAL`, file bytes unchanged.
7. **Control** `TestBadCRCInOlderSegmentIsRefused`: bit flip in the tail of a non-last segment.
8. **Control** `TestCRCValidUndecodableRecordIsRefused`: valid CRC with an unknown type; valid CRC with a short Entry payload; both at
   the tail; `ErrCorruptWAL`, `Repaired` false, file untouched. Green today and must stay green after the fix (guards the key above).
9. **Control** `TestOrdinaryTornTailStaysRepaired`: a cut at every offset (as `wal_test.go:223`) still repairs, then reopen reports
   `Repaired` false. **Red** half `TestRepairedTailStaysRepaired` for a bad-CRC tail: reopen, append, reopen again (like
   `wal_test.go:257`); the on-disk length equals the last good offset plus the new appends.
10. **Red** `TestRepairIsReported`: `OnRepair` called once with segment, offset, `Bytes` = dropped length; not called for a clean or a
    refused open. `TestWALRepairedMetric` (`internal/metrics`; red, new API): `wal_repairs_total` +1, bytes counter + dropped length.
11. **Red** `TestDiskStorageRepairsTailAndRefusesMidLog` through `OpenDiskStorage`.
12. `FuzzWALReplayTail`. **Generator:** a fixed, valid prefix of k >= 2 records written by the test, followed by fuzzer-controlled tail
    bytes that replace the last record's region (the tail may be empty, a damaged record, an intact record, or several records). A
    restriction to "damage inside the last record" would not make the last record invalid (an unchanged or cleanly truncated record is
    valid, and a mutation can yield another valid one), so soundness comes from the oracle, not from the generator.
    **Oracle (ordered effects):** an independent test-local frame walker (own length check and `crc32` Castagnoli, then the package
    decoders; it does not call `readRecord` or `replay`) finds the first framing failure `good` and every offset after it holding a
    record that independently CRC-validates **and** decodes. A **test-local reference model** then applies the validated records in
    file order with their real effects: an Entry at index <= the current last **cuts** the model log first (a valid conflicting entry
    legitimately changes the prefix), a `DiscardSuffix(n)` (once T3.11 lands) cuts to `Index < n`, HardState and SnapshotMeta replace
    their values. The expected state is the model's state; "the original prefix followed by validated records" is **not** the oracle.
    Required outcomes: **refuse (`ErrCorruptWAL`, file bytes unchanged)** for every framing failure with a valid record later, and for
    every CRC-valid undecodable or unknown-type record; **succeed with exactly the modeled state** for clean input and for a bad or torn
    record with nothing valid after it (the last record may be cut at a tear; `Repaired` true only then). Never panics. **Reopen is
    idempotent:** a second `Open` returns the same state, `Repaired` false and identical file bytes. The walker's known-type table is a
    shared helper so T3.11's record type is added in one place.
    **Seeds** (all go through the same oracle): intact tail; every-byte xor of the last record; truncations at every length; zeroed
    tails; oversize length; and **"valid record after the damage"**: a damaged record followed by an intact record. That seed is why the
    generator is "prefix fixed, tail free" rather than "mutate only the last record": it needs bytes after the damage, and the oracle
    expects `ErrCorruptWAL` for it (the walker finds a valid later record). 60 s clean.
The power-loss-after-each-repair-op test is **T3.8** (`TestRepairIsDurable`), not here.

## Implementation notes
- Keep `ErrTornRecord` handling; extend the repairable set only through the "nothing valid follows" check.
- A short final record with a plausible header is `ErrTornRecord` or `ErrRecordTooLarge`; both go through the same check.
- Do not add a segment-relative checksum or any format change.
