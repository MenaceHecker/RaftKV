## State handling
- **Polling:** one `setTimeout` loop (never `setInterval`) on `GET /v1/cluster`: 1 s visible, 5 s when `document.hidden`; the gateway caches at 1 Hz so faster is useless. SSE events `state, node_up, node_down, chaos, resync` trigger one debounced (250 ms) refetch; the cluster doc, not SSE, is the source of truth for panels 1, 2 and 4 (SSE has no `lastApplied` or `logLen`). A node with `lastContactMs` > 5000 is drawn stale. 429 -> wait `Retry-After` (min 1 s). Three consecutive failures (network, timeout, 5xx other than 429) -> mode `replay`.
- **SSE:** native `EventSource` (injected constructor), **one per tab**, listeners for the 8 names (`state node_up node_down snapshot commit chaos verify resync`), unknown names ignored, malformed JSON dropped and counted, never thrown. Native reconnect (readyState CONNECTING) already sends `Last-Event-ID`, so the wrapper keeps the last `id`, ignores ids <= it, and does not interfere. After 3 consecutive `error` without an `open`, or readyState CLOSED (HTTP 429/503 cap, wrong CORS: a browser cannot read the status), the wrapper recreates the source with jittered exponential backoff 5 s doubling to 60 s (5 s floor = the gateway's `Retry-After`); a recreated source has **no Last-Event-ID**, so it marks a gap: refetch the cluster and add a timeline row "events may be missing". SSE trouble alone never switches to replay; the banner says "live events unavailable (viewer limit?)" and polling continues. `resync`: replace the cluster doc with its payload, add a timeline row, do not clear the timeline. Close the stream after 60 s of `document.hidden` (frees one of the 3 per-address slots), reopen on visible. Fetch-based SSE would expose status and `Last-Event-ID`: rejected for size (OPEN QUESTION 5).

## Replay mode
- **Format** `public/recording.jsonl`, one JSON object per line, `v:1`: line 1 `{"v":1,"kind":"header","recordedAt":ISO,"durationMs":N,"synthetic":bool}`; then `{"t":ms,"kind":"cluster","data":<cluster doc>}` (one per second), `{"t":ms,"kind":"event","id":N,"name":"<sse name>","data":<payload>}` (verbatim), `{"t":ms,"kind":"verify","data":<report>}` (when `verify` `done` fires), sorted by `t`. Unknown kinds skipped; a bad line is skipped and counted; a file with no header is rejected and the UI shows "no recording".
- **Capture** (`scripts/record-session.mjs --gateway URL --out FILE --seconds N`): connects to the real `/v1/events` and polls `/v1/cluster`, writes the lines above with relative `t`, fetches `verify/last` on a `done` event; **public access only, never sends `Authorization`**; refuses to write if any line contains the substring `Bearer`. The card specifies and tests it against the mock gateway; **running it on the live cluster during a scripted demo (kill leader, isolate, heal, one verify run) belongs to D8**, which commits the real `recording.jsonl`.
- **Playback:** the engine takes an injected clock and replays at 1x (`cluster` lines set the doc, `event` lines feed the same reducers as live SSE), loops at the end with a timeline row "recording restarted". `ModeBanner` shows a persistent **REPLAY** badge with the recording date and "live gateway unreachable" or "replay only"; Controls, KV and Run are disabled with the reason "replay is read-only"; the Verifier shows the recorded report.
- **Switching:** start in live if `VITE_GATEWAY_URL` is set and `VITE_REPLAY_ONLY` is not `true` and the URL has no `?replay=1`; the first `cluster()` must succeed within 3 s, else replay. In replay with a gateway configured, probe `/healthz` then `/v1/cluster` every 30 s (jittered) and return to live on success; a 429 is "reachable", not "down". The recording is a same-origin static file (`/recording.jsonl`) so the link works with no AWS at all; a test runs the app offline (fetch to the gateway rejects, `EventSource` never opens) and sees REPLAY and a populated cluster.
