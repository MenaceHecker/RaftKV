# T5.7: mutation suite (RUNBOOK 8.6)

Planner: Claude, read-only. Based on `origin/main` ea0dd7a plus the T5.6 card (`docs/tasks/T5.6.md`, not yet implemented). Claims come from
reading; **no test was run and no timing was measured**. "UNVERIFIED" marks detection I could not confirm by reading. Branches:
`test/t5-7-mutation-red`, then `feat/t5-7-mutation`. RUNBOOK 11: "never cut the mutation suite"; nothing below may be dropped or weakened.

## Goal
Nine known bugs sit behind build tag `faultinject`. For each, a named scenario and seed range must make an oracle (linearizability checker,
election-safety or new committed-log monitor, convergence, core panic) fail. The suite goes red if any bug is undetected, cannot pass
vacuously, is enforced in CI, and its results are written to `docs/CHAOS_RESULTS.md` (does not exist yet). Default build is unchanged.

## Invariants touched
RUNBOOK 7.1 (all five safety properties, as oracles), 7.2 (fsync before reply, no-op, 5.4.2 commit rule, vote check), 7.4 (dedupe, deposed
leader reads), 7.5 (session table in snapshot). Production behaviour must not change; no mutation may add a storage write
(`internal/determinism/storagemarking_test.go:19` requires every core storage write to mark its failure).

## Decisions (proposed; human confirms under OPEN QUESTIONS)
1. **Switch package** `internal/faultinject`: `switch.go` (no tag: `type Switch`, 9 consts, `Name()`, `All()`), `off.go` (`//go:build !faultinject`:
   `func Active(Switch) bool { return false }`, inlined and dead-code-eliminated), `on.go` (`//go:build faultinject`: plain `[N]bool`, `Set`,
   `Enable(name) error`, `init()` reads env `RAFTKV_FAULTINJECT=a,b`; an unknown name panics at init so a typo cannot run clean).
   Call sites are only `if ... || faultinject.Active(faultinject.X)`. Raft imports no `os`/`time`/`rand`; `internal/determinism/determinism_test.go:13-22`
   forbids those in `../raft` and `../statemachine`, and `parsePackage` (`:130`) ignores build tags, so tagged files there are checked too. The
   new package is outside `pureDirs`, so it may read the env; the pure packages only call `Active`. Non-atomic bool: set before a run, never
   `t.Parallel`; `sync/atomic` is forbidden there (`:20`).
2. **Runtime selection:** in-process `faultinject.Set` with `t.Cleanup` reset (tests); env var for `chaosrun` reproduction.
3. **Suite of record is an in-process Go test**, `chaos/mutation_test.go` (`//go:build faultinject`), not a subprocess: it recovers panics per run and
   names the oracle. One extra test builds `chaosrun` with the tag and checks the exit contract (assumption A1) for bug 6.
4. **Detection is classified, not inferred from "failed".** New `chaos/oracle.go`: `Classify(RunResult) Oracle` in {None, Linearizability,
   Convergence, ElectionSafety, CommittedLog, Panic, Inconclusive}. `RunResult.Err` also carries Undecided (`scenario.go:179`), too few ops, a
   missed `RequireFaults` and harness errors; those are **Inconclusive and count as NOT detected**. Election-safety errors (`cluster.go:403,503`)
   gain a sentinel (`%w`) so they classify by `errors.Is`, not string match.
5. **New oracle, committed-log monitor** (RUNBOOK 7.1 says "checked after every step"; only election safety exists, `cluster.go:391`): after each
   `Tick`, per up node record `TermAt(i)` for every `i <= CommitIndex()` not yet recorded (skip ErrCompacted); a later different term at a
   recorded index, a leader missing a recorded entry, or `machines[id].Applied() > n.CommitIndex()` is an error. Sentinel `ErrCommittedLog`.
   Needed for bugs 2, 3, 4, 9 to be flagged early and reliably. Awaiting approval, see OPEN QUESTIONS 1.

## Per-bug spec (switch, injection point verified by reading, oracle, trigger, confidence today)
1. `skip-fsync`. `internal/storage/wal.go:611` `if w.policy == SyncAlways {` in `WAL.write` (callers: AppendEntries `:531`, SaveHardState `:548`)
   becomes `&& !Active`. Oracle: linearizability (acked write lost) or election safety (lost vote, two leaders). **Cannot be caught today:**
   `runOnce` uses `SyncNever` (`scenario.go:139`), so the mutated line never runs; `Config` has no FS (`cluster.go:83-93`); `Crash` (`:450`) never
   calls `faultfs.Crash` (`internal/storage/faultfs/faultfs.go:396`); in-memory `Restart` (`:467`, `openStorage` `:162`) wipes the node. Needs
   `Config.FS`/`Sync`, `Cluster.PowerLoss()` (crash all, then `fs.Crash(DropTail)`), new scenario `scenarioPowerLossAfterAck` (disk, `SyncAlways`,
   ack writes, power-loss, restart, read before any new write; `scenarioWholeClusterRestarts` `:1013` writes before reading, so it hides loss).
   Seeds 1-20. Confidence: LOW today, MEDIUM with the harness work.
2. `truncate-on-stale-append`. `internal/raft/log.go:92` (`case conflict == 0:` does nothing): under the switch also `storage.Append(entries)`,
   which truncates the suffix (`storage.go:159-160`). Trigger: duplicated and delayed AppendEntries, `scenarioLossy` (`DuplicateRate 0.1`) and
   `scenarioLeaderChurn`, seeds 1-50. Oracle: CommittedLog monitor; else Ready panic (`node.go:283`, "reading committed entries") or
   Linearizability. Leader resend repairs a truncated follower, so loss needs a leader change right after. Confidence LOW-MEDIUM, UNVERIFIED.
3. `commit-previous-term`. `internal/raft/replication.go:238` `if err != nil || t != n.term` drops the `t != n.term` half. Figure 8 (paper 5.4.2) is
   **masked here**: the new leader's no-op (`node.go:500`) rides in the same batch as old entries and the default append limit is 1 MiB
   (`node.go:11,194`), so an ack never covers the old entry alone. Needs `Config.MaxAppendBytes` in chaos `Config` (`cluster.go:187-194`) small enough to
   page, and `scenarioFigure8` (5 nodes, partitions not crashes, since in-memory crash is amnesia). Oracle: CommittedLog, else Linearizability. Confidence: LOW.
4. `skip-vote-uptodate`. `internal/raft/election.go:45-47` (`granted := canVote && upToDate`) and the PreVote twin `:121-123` (PreVote is on,
   `cluster.go:193`, so both must be mutated). Trigger: a lagging node wins after a partition, `scenarioMinorityPartition`, `scenarioLeaderChurn`,
   `scenarioLeaderPartitioned`, seeds 1-50. Oracle: Panic at `log.go:94` ("conflicts with committed index") or CommittedLog. Confidence MEDIUM, UNVERIFIED.
5. `local-read`. `internal/raft/readonly.go:61` `if n.isSoleVoter()` gains `|| Active`, skipping the heartbeat quorum round. **Existing
   `scenarioStaleLeaderRead` (`scenarios_test.go:422`) will NOT catch it:** it reads after 120+ ticks, but CheckQuorum (`cluster.go:192`) demotes the
   isolated leader within about two election timeouts (`node.go:322-330`), so `handleReadIndex` returns ErrNotLeader (`readonly.go:50`) before the
   mutated line. Needs `scenarioStaleReadWindow`: partition the leader, tick one at a time until a new leader commits a write, then at once
   `ReadFromAndSettle(old)`; if the old leader already stepped down, return an error (Inconclusive), never a pass. Oracle: Linearizability. Seeds 1-50. Confidence MEDIUM.
6. `skip-dedupe`. `internal/statemachine/session.go:36` (`if clientID == NoClient {`) gains `|| Active`; sessions are then never consulted
   (`kv.go:142`). Trigger: `scenarioRetriedWriteIsNotAppliedTwice` (`:843`): resend of an acked write after a later write, read sees the old value.
   Oracle: Linearizability. Seeds 1-5. Confidence HIGH. Also `scenarioRetriesAcrossLeaderChanges` (`:885`).
7. `skip-noop`. `internal/raft/node.go:500-508` wrapped in `if !Active`. Safety survives: reads need a current-term commit
   (`readonly.go:57,111-117`) and `maybeCommit` refuses old terms (`replication.go:238`); the cost is liveness (reads fail with ErrLeaderNotReady
   until a write arrives). **No existing oracle flags it**, and T5.6's liveness check ("a write succeeds") passes because writes still commit. Needs a new
   liveness oracle `Cluster.AwaitReadable(maxTicks)` and `scenarioReadAfterElection` (replicated entry in the old term, leader change, reads only, no writes,
   must reach StatusOK). Oracle: Liveness, added to `Classify`. Confidence: NONE today, MEDIUM with the new oracle.
8. `snapshot-omits-sessions`. `internal/statemachine/kv.go:236` `buf = kv.sessions.encode(buf)` becomes an empty table (`appendUint64(buf, 0)`) under the
   switch; decode accepts it (`session.go:107-123`). Existing snapshot scenarios (`:665-855`) mostly **miss it**: writers write again after the install, so
   session bytes reconverge before `Converged` (`cluster.go:786`) compares them. Needs `scenarioResendAfterSnapshotInstall` (write, `CompactAll`, crash and
   restart a node so it installs, `Resend` the old write, tick, `Converged`). Oracle: Convergence, else Linearizability. Seeds 1-20. Confidence MEDIUM.
9. `apply-beyond-commit`. `internal/raft/log.go:161-170`: `hi = l.committed+1` becomes `l.lastIndex()+1`, and the guard `i > l.committed` at `log.go:154` is
   skipped under the switch (otherwise `appliedTo` panics at once; the card tests the silent variant, the panic is defence in depth). Trigger:
   `scenarioLeaderPartitioned` (`WriteTo` the isolated leader, `cluster.go:630`) and `scenarioLeaderCrash`. Oracle: CommittedLog (`Applied > CommitIndex`), then
   Linearizability (write acked at `cluster.go:740`, entry later truncated). Seeds 1-50. Confidence HIGH with monitor, MEDIUM without.

## Implementation notes
- Comments in new non-test code must avoid "for now", "yet", "once", "lands" near the word "phase" (`staleclaims_test.go:11-20`).
- The engine stops a bug at its first detection; an undetected bug runs its whole range, then the suite fails and prints the seeds tried.
- A panic is Detected (core assertion) but reported as Panic with the message; the reason column in `CHAOS_RESULTS.md` is the oracle actually
  fired, and a different oracle than expected is recorded, not failed. Table columns: bug, switch, file:line, scenario, seeds tried, first seed, oracle.
- `CHAOS_RESULTS.md` is written by the test under `WRITE_CHAOS_RESULTS=1`, no timestamps; CI regenerates and `git diff --exit-code`s it.
- Checker: `Check` turns Pending into Unknown (`checker.go:82`) and an Unknown write may take effect anywhere after invoke (`:122`), so a lost
  write reported Unknown is never flagged. Mutation scenarios should read after quiescence from acked (StatusOK) writes. Failed ops are dropped (`:79`).
- The scenarios are scripted; a seed varies only message fate and election timeouts (T5.6 card), so "seeds 1-50" is a search, not a proof.
