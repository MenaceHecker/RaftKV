# T3.19: a node outside its own configuration must not campaign or become leader

## Goal
A node whose current configuration does not contain its own id still ticks as a follower, times out, increments and persists its term,
sends vote requests, and when it wins calls `becomeLeader`, which dereferences `n.progress[n.id]` (nil) and panics. Make such a node
inert for elections: it never starts a campaign or pre-campaign, never bumps its term, and `becomeLeader` returns an error instead of
panicking if ever reached. Raft behaviour for members is unchanged.

## Facts from the code (cb273a8)
- `Tick` (`internal/raft/node.go:319-345`) runs the election timeout for `Follower`, `PreCandidate`, `Candidate` with no membership test, then calls
  `campaign()` (`election.go:3`), which goes to `preCampaign()` or `realCampaign()`.
- `becomeCandidate` (`node.go:458`) persists `term+1` and votes for itself before anything checks membership; the self vote is
  `votes = {n.id: true}` even when `n.id` is not a voter. `becomePreCandidate` (`:474`) does the same without persisting.
- `becomeLeader` (`node.go:494-516`) builds `n.progress` from `conf.members()` and then writes `n.progress[n.id].match` (`:508`): nil dereference
  when the id is absent. Reached from `handleVoteResponse` (`election.go:77`) and from `realCampaign` when `isSoleVoter()`.
- `voteGranted`/`voteLost` (`membership.go:138-152`) count only voters, so a non-member can still reach a majority from the other nodes' grants.
- `MsgCampaign` is handled through `Step` (`node.go:349`) and also reaches `campaign()`.
- Existing coverage: `selfremoval_test.go` (`TestLeaderRemovingItselfDoesNotPanic`, `TestLeaderStandsDownAfterRemovingItself`,
  `TestClusterElectsAReplacementAfterTheLeaderLeaves`) and chaos scenario "the leader removes itself from the configuration"
  (`chaos/scenarios_test.go:508`, moving to `chaos/scenarios.go` in T5.6). None runs a removed node long enough to time out and campaign

- **Unverified:** which seeds trip it other than 7; whether the removed node reaches leadership via real votes or `isSoleVoter`.

## Rule to implement (the contract the tests pin)
`promotable()` is true iff `n.id` is in `conf.voters` or, when joint, in `conf.incoming` (a node being removed stays promotable only while it
is still a voter of the effective configuration; match etcd and the dissertation). `campaign()` returns nil without side effects when
`!promotable()`: no state change, no term bump, no persist, no messages, and `electionElapsed` is reset so it is not re-evaluated every tick.
`MsgCampaign` follows the same path. `becomeLeader` returns `fmt.Errorf("raft: %d is not in its own configuration")` when
`n.progress[n.id] == nil` after building progress (defence in depth; never panics). A non-member still **responds** to others normally
(vote requests, appends) until it learns it is removed; this card does not change that.
