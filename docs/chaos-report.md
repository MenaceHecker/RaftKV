# RaftKV chaos report

Generated by `go test ./chaos -run TestChaosReport`.

Every scenario drives a cluster of real Raft nodes over a simulated,
fault-injecting network, then hands the observed client history to a
linearizability checker. A scenario passes only when every node converged
to identical state *and* an ordering exists that explains every result a
client was given.

Each scenario runs across several seeds. A seed fixes the entire schedule,
including message delays, drops, and election timeouts, so any failure here
can be reproduced exactly by re-running with that seed.

The operation counts read ok/failed/unknown. An unknown operation is one a
client never got an answer for, which is not a defect: it is the ambiguity
a real client faces, and the checker is required to find an ordering that
works whether or not each one took effect.
