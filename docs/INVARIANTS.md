## 7.6 Which chaos check covers which injected bug (RUNBOOK 8.6)
The mutation suite (`go test -tags faultinject ./chaos -run TestMutationSuite`, results in docs/CHAOS_RESULTS.md, regenerated and diffed by CI) is the check that the
oracles above can fail. 9 of 9 injected bugs were detected, and a control with every switch off was clean. A bug counts as detected only when an oracle flags the run; a run with no
verdict is inconclusive. Detection depends on the seed range searched: bug 4 needed 152 runs over several scenarios (first seed 2), and bug 3's scenario assigns roles by which node the seed elects.

| # | Injected bug | Property it breaks | Oracle that caught it |
|---|---|---|---|
| 1 | skip fsync before acknowledging | persist before replying (7.2 #1) | linearizability checker |
| 2 | truncate the log on a stale append | truncate only on a real conflict (7.2 #8); committed entries kept | committed-log monitor |
| 3 | commit a previous-term entry by counting | §5.4.2 (7.2 #10); Leader Completeness | committed-log monitor |
| 4 | grant votes without the up-to-date check | one vote and up-to-date rule (7.2 #5); Leader Completeness | committed-log monitor |
| 5 | serve a read from a deposed leader | linearizable reads (7.4) | linearizability checker |
| 6 | skip client dedupe | dedupe (7.4) | linearizability checker |
| 7 | leader skips the no-op after election | no-op on election win (7.2 #11) | read-liveness check |
| 8 | snapshot omits the session table | snapshot contents (7.5) | convergence check |
| 9 | apply entries beyond commitIndex | apply only committed entries (7.2 #13) | committed-log monitor |

What this does not show: the suite proves these nine bugs are caught, not that others would be; the scenarios are scripted, so seeds vary message fate and election timeouts only.
Log Matching and Leader Append-Only have no oracle of their own (7.1).
